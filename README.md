## IEPL、IPLC、IX 到底有什么区别

这三个词经常被混着用，其实对应三种不同的接入方式。IEPL（International Ethernet Private Line，国际以太网专线）和 IPLC（International Private Leased Circuit，国际专线电路）都属于内网专线：数据在国内入口和海外出口之间走运营商的专用通道，不经过公网，所以延迟稳定、不受公网拥塞和防火墙波动影响。两者的差别主要在技术层级——IPLC 是点对点的物理层电路，IEPL 是以太网层的专线，可以支持多点组网，对个人和企业租用来说实际体验差异不大。

IX 则是另一条路线：不拉物理专线，而是借助阿里云、腾讯云这类云厂商的内网通道完成跨境传输。前提是你的业务本来就跑在支持范围内的云服务器上，相当于"借道"云内网，成本更低。

| 线路类型 | 接入方式 | 适合谁 |
| --- | --- | --- |
| IEPL / IPLC | 直连专线入口，绑定一个省份连入 | 本地宽带、办公室网络直接连 |
| IX | 经云厂商内网接入，不限连入省份 | 业务已部署在阿里云/腾讯云等云上 |

Mkcloud 的产品资料给出了各线路的端内参考延迟：广港、深港 IX、厦港、泉港为 1~2ms，沪港 21ms，沪日 25~28ms，沪美 124~134ms。注意这是线路内部的参考值，不是你本地到目标网站的全程延迟——本地到入口、出口到目标服务这两段仍然走公网，选型时要分开看。

## IEPL 专线 VPS 的实际用法和边界

Mkcloud 的每台专线 VPS 分配 1 个独立入口 IP 和 1 个独立出口 IP。你连接入口，在服务器里打开浏览器、店铺后台或 API 客户端，访问请求自动从专线出口发出。这个形态决定了它的适用边界：

- **适合**：美区/欧区店铺后台运营、海外广告账户管理、素材上传、跨境数据同步、API 调试这类"从服务器向外访问"的任务。
- **不适合**：需要公网入站的业务。出口 IP 不接受外部连入，挂公开网站、接支付回调、跑邮件服务器或游戏服务端都不行，这些需求要另找产品。

还有两点下单前必须知道。第一，直连产品入口绑定一个省份，只有该省份的 IP 能连入，换地方用可以自助切换绑定；IX 产品不限省份，但必须从支持范围内的云厂机器接入——深圳入口支持阿里云、腾讯云、百度云国内全网及火山云、华为云华南，上海入口另外支持 UCloud 华东。第二，账号需要实名认证，平台明令禁止用于机场等业务，只支持合法合规的跨境业务用途。

## 常见问题

**IEPL 专线一个人能用吗，还是只能企业买？**
个人和企业都可以购买，但需要实名认证，且只能用于合法合规的业务用途。部分独享产品在购买时需要提交中国身份信息实名。

**人在北京，能用广州入口的广港专线吗？**
直连产品绑定一个省份，只有绑定省份的 IP 能连入入口。你可以在下单后把绑定省份切换到北京，但本地到广州入口这段公网延迟能不能接受，建议先测试再决定。

**共享和独享到底怎么选？**
看任务形态。店铺后台、广告投放这类间歇性操作，共享档的峰值带宽完全够用；每天数小时持续上传、大文件同步，才值得为独享带宽多付几倍的价格。

**IX 专线是不是比直连划算？**
IX 套餐本身更便宜，但它要求业务已经跑在阿里云、腾讯云等支持的云服务器上，你还要算上前置云机本身的费用。没有现成云厂机器的话，直连是更简单的起点。

选 IEPL 专线的逻辑其实不难：先确认业务能不能在 VPS 里跑，再按目标出口（香港、日本、美国）选方向，然后看本地接入条件定直连还是 IX，最后按流量和带宽需求选档。价格只是其中一个变量，入口能不能连上、流量够不够用，比线路名称重要得多。拿两个档位各买一个月实测，比看任何测评都管用。
